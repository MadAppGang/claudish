## Fleet-Rollout Verification (hard rule, mandate 2026-09-12)

**A fleet-affecting change declared DONE requires a measured per-consumer verification artifact, produced in the same session** — for every client: where it actually lands, read from the live config/path, not from the change's intent. "The container moved" is not "the fleet migrated". The 2026-09-05 cutover had this and passed — then the ARR flip was silently reverted on 07/09 15:37 (byte-identical restore of the pre-flip `web.config`), and no cycle caught it until the 11/09 hub outage exposed it: 2 779 requests / 263.6M tokens served by the po-203 local cascade (106M on PAYG), invisible to the hub. Consequences, now standing:

- **Surveillance covers the path, not just the traffic**: a cycle checking hub health also checks the entry points that feed it (ARR backend, per-machine base URLs) — a silent revert must be catchable within one cycle, not one outage.
- **An outage detected is an outage escalated — in the SAME cycle** (DM URGENT + dashboard). "Chronic" thresholds (#80-style counts) never apply to a total outage.
- **An issue treated halfway is an issue in failure**: no next grain until the current issue's DoD is met or the rescope is explicitly recorded.
- Rollback of a fleet change goes through the same channel as the change: an unlogged revert of shared infra (IIS web.config, .env, NAT) is an incident, not a fix.

## Build, Release, Versioning

- `bun run build` (CLI + macOS bridge bundles) · `bun run dev`. Use **bun**, never npm or yarn.
- **Releases are handled by CI/CD — never run `npm publish` by hand.** Bump version → conventional commit → `git tag -a vX.Y.Z -m "…"` → `git push origin main --tags`.
- **Every PR that resolves an issue carries `Closes #NN` in its body.** GitHub only auto-closes on merge when the keyword is present: a descriptive "Issue #79 asked for…" leaves the issue open with its fix already merged and live, and the registry drifts silently. Measured 2026-09-12 — #65, #79 and #80 were all in exactly that state (three merged fixes, three orphaned issues).
- **A version bump touches three files, all mandatory**: root `package.json`; `packages/cli/package.json` (**this is what CI publishes — stale here and `npm publish` fails**); `packages/cli/src/version.ts` (fallback `VERSION`, so compiled binaries with no package.json still report correctly).

## Model Routing (v4.0+)

Syntax `provider@model[:concurrency]` — `google@gemini-2.0-flash`, `or@deepseek/deepseek-r1`, `ollama@llama3.2:3`. Bare names auto-detect (`gpt-4o` → OpenAI, `gemini-*` → Google). Shortcuts (`g@ oai@ or@ openrouter@ mm@ mmax@ mmc@ kimi@ moon@ glm@ zhipu@ gc@ llama@ ll@ litellm@ ollama@ lmstudio@` + aliases) plus any custom-endpoint name: full table in `docs/settings-reference.md` §5.2 — except **`cx@` / `codex@` → OpenAI Codex (Responses API), which that table does not list**; this file is its only record.

Gotchas:

- **A role's `modelMap` entry picks the LANE; since #218 it also pins the VERSION, but only on the native lane and only for `claude-*` targets.** `NativeHandler.handle` forwards `payload.model` verbatim, so before the pin the resolved target never reached the wire and `modelMap.opus` was a no-op on the version axis — measured on the hub 2026-09-22, the map read `claude-opus-4-8` for weeks while **6 487 consecutive native responses over 48 h** were served as `claude-opus-5`, the id the clients named; editing it to `claude-opus-5-5` and reloading still gave 34/34 `claude-opus-5`. `resolveNativeModelPin()` now rewrites the body inside `handleWithCascade`'s loop — there, not at the route, because the cascade re-resolves the handler each attempt and only the attempt landing on `NativeHandler` may carry a bare Anthropic id (the original is restored on a failed attempt, so the mutation never outlives it; `count_tokens` takes the same pin or the client's context accounting drifts). ⚠ **The guard is `startsWith("claude-")`, NOT "is bare" — the two are different predicates and conflating them misfires on this hub**: `sonnet: "glm-5.3"` is bare too, and is kept off the native lane only by resolving to a remote handler; drop it from the routing table and `isNative` (`!includes("/") && !includes("@")`) accepts it, at which point a bare-only guard would put `glm-5.3` on the Anthropic wire — strictly worse than the passthrough it replaced, which at least sent a real Claude id. Kill switch `CLAUDISH_NATIVE_MODEL_PIN=0`, read per request (same container rule as every "read per request" knob: a new value enters a container only at its next recreate — compose carries it, #310); only an explicit `"0"` disarms. There is no Anthropic-side floating `-latest` to point at (dateless ids are pinned snapshots), and the hub holds **no Anthropic credential** (0 non-empty in env and in `config.json`), so it cannot query `/v1/models` to auto-resolve one — #219 tracks doing it from the OpenRouter catalog, where the id spelling differs by **dots vs dashes** (`claude-opus-5.5` vs `claude-opus-5-5`).
- **The native lane refuses to forward a credential that is not Anthropic's (#296), on both `/v1/messages` and `count_tokens`.** Post-swap credential state is checked before the fetch: no credential at all (shape A — the proxy-key swap removed the client's token and no `apiKey` was substituted) or a foreign, non-`sk-ant-` credential (shape B — a Bearer belonging to another party, the WAN-seat shape measured 30/09–01/10 as 40 × upstream `Invalid Bearer <redacted>`) answers locally with a labeled `403 permission_error` and marker `[Native] refused — no Anthropic credential to send (shape=A|B, model=…)`, zero upstream fetch. The `sk-ant-*` OAuth passthrough (ai-01) and the swap-with-`apiKey` path are untouched; kill switch `CLAUDISH_NATIVE_FOREIGN_TOKEN_GUARD=0` (read per request). ⚠ The refusal wording is load-bearing: `isQuotaExhaustion` arms on 403 bodies naming a quota wall, so the message may never contain "usage limit"/"quota exceeded" class words — pinned by test against the real predicate. Since #305, a **mixed** pair (one `sk-ant-` credential + one foreign sibling) is **stripped, not refused** — the `sk-ant-` credential still authenticates (the authorized lane survives whatever the client's header habits), the foreign token never leaves (same pattern as the relay's stale-`x-api-key` drop); same kill switch, and `CLAUDISH_NATIVE_HEADER_NAMES_LOG=1` is the AC-1 instrument (header NAMES only) logging which auth headers reach the native lane. ⚠ **On the hub it sees post-relay headers, not the client's**: a relay deletes `x-api-key` on every forward (`relay.ts`, the stale-proxy-key guard) and a NOMINAL relay never enters `NativeHandler`, so for a relayed client (ai-01's Opus, via its sidecar) the hub can only ever report `authorization` or `(none)`. Only directly-attached clients are measured there. The strip makes that measurement non-decisive: it is safe whatever the client sends.
- **`defaultProvider` is a last-resort fallback, not a front-of-line override.** It is appended to the *end* of each bare-name chain (deduped — `or` ≡ `openrouter`) and only catches models whose chain has zero credentialed providers. Explicit `provider@model` is never affected. Precedence: `--default-provider` > `CLAUDISH_DEFAULT_PROVIDER` > config `defaultProvider` > `OPENROUTER_API_KEY` present > hardcoded `openrouter`.
- **LiteLLM auto-promotion was removed** (commit 5 of the model-catalog/routing redesign; see `default-provider.ts`). `LITELLM_BASE_URL` + `LITELLM_API_KEY` no longer makes LiteLLM the default — set `defaultProvider: "litellm"` explicitly. ⚠ `docs/settings-reference.md` §6.1/§6.3 still documents the legacy promotion; that text is **stale — trust the code**.
- **Vendor prefix resolution is exact-match only** — find the right prefix, never guess the model. Dynamic provider catalogs are PRIMARY; `OPENROUTER_VENDOR_MAP` is a cold-start fallback only. Resolution happens in `proxy-server.ts` **before** handler construction, through the sync `resolveModelNameSync()` (in-memory caches + `readFileSync` — do not make it async).
- **Custom endpoints**: `apiKey` expands `${VAR_NAME}` from the environment (never hardcode secrets); entries failing Zod validation **emit a stderr warning and are skipped — they must never crash the proxy**. Endpoints inject themselves through `registerRuntimeProvider()` / `registerRuntimeProfile()` (`providers/custom-endpoints-loader.ts`); the full `customEndpoints` schema (`modelPrefix`, `CLAUDISH_CONFIG_DIR`, per-endpoint key vars) is in `docs/settings-reference.md` §7.
- **`omitReasoningContent`** (custom endpoints, default `false`) drops `reasoning_content` from outbound assistant messages, for backends that validate their body strictly. It is needed because the OpenAI converter emits that field whenever history holds a thinking block — **independent of any opt-in**, since the consumers disagree: DeepSeek *requires* it echoed back, Kimi K2.5 needs it from turn 2, GLM ignores it. Mistral answers `HTTP 422 extra_forbidden` and fails **every** turn of a thinking-mode session. ComposedHandler's thinking-block strip cannot reach it: on the OpenAI wire that strip is a **structural no-op** (it runs after `convertMessages`, by which point content is flattened and reasoning hoisted to a sibling scalar) — hence a separate `stripReasoningContent()` in `openai-messages.ts`. Incident of 2026-08-20 and the measurement that Mistral's `zai-glm-5-2` emits no traces at all: `docs/reference/proxy-pipeline-notes.md`.
- **The MiniMax `forced` thinking chain has TWO filters, and #295 + #324 B1 lift one each (#324).** Outgoing: `MiniMaxModelDialect.shouldFilterThinking()` returns false under `forced`, so the response's thinking block (and its signature) reaches the client. Incoming: ComposedHandler's history strip (the `preserveThinkingInHistory()` gate) used to remove the echoed block before it reached M3 — the chain repaired on one wire and broken on the other (measured by a coordinator probe: forwarded assistant turn carried only `[tool_use]`, M3 fell back to the mute T4a shape). The fix is a per-block hook `preserveThinkingBlock(block)` consulted ONLY inside the strip loop (default false = strip-everything, byte-identical for every other provider); MiniMax overrides it: under `forced`, a block whose signature is unsigned or a **64-lowercase-hex digest** is MiniMax's own and survives intact, anything else is stripped. The discriminant is measured, not supposed: M3's implicit signature is the SHA-256 of the empty string (`e3b0c442…`, fixtures `minimax-m3-anthropic-implicit-signature-r10324/r10416`), M2.5's digests vary but stay 64-hex (`m25-turn1`), `m25-turn2/3` are unsigned — an Anthropic signature is a long opaque base64 blob (the cascade-switch shape: an Opus session that fell to a MiniMax step) and never matches. Deliberately NOT the boolean `preserveThinkingInHistory()`: it also feeds `reasoningRoundtrip` in `convertMessages` (OpenAI wire, `reasoning_content` echo-back); MiniMax lanes run anthropic-sse, where the per-block hook is the only consulted seam, and flipping the boolean would emit `reasoning_content` on OpenAI-shaped routings the policy was never measured on (pinned by unit test). Suites: `composed-handler-minimax-thinking.test.ts` (route, 2-turn, upstream body inspected) + `minimax-model-dialect.test.ts` (discriminant matrix).
- **Local model APIs report `prompt_tokens` as the FULL conversation context each request**, not a delta. `writeTokenFile` therefore assigns (`=`) input tokens rather than accumulating (`+=`).
- **The three input counters ship TOGETHER on every terminal `message_delta`, and a zero `input_tokens` is a trap (#179).** `splitPromptTokens()` (`stream-parsers/usage-cache-split.ts`) derives `input_tokens` / `cache_read_input_tokens` / `cache_creation_input_tokens` from `prompt_tokens` in ONE place, clamped so the three always sum back to it — because **Claude Code reconstructs the conversation size by summing them raw**, with no coalescing (verified in the shipped bundle, identical in 2.1.17 and 2.1.273: `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`, feeding the occupancy percentage). Two consequences that look like style and are not: (a) emitting a reduced `input_tokens` **without both siblings** understates the context by exactly the cached share — the shape #99 was opened for, which silently disarms auto-compaction; (b) `message_start` must seed both cache counters at an explicit **0**, because the client's per-key merge takes a delta only when it is `> 0` (`K.x !== null && K.x > 0 ? K.x : A.x`) and an absent seed key therefore returns `undefined`, turning that raw sum into `NaN` — `output_tokens` uses `??` and coalesces, the three input counters do not. Hence the **`fullyCached` unsplit rule**: on a turn whose input is entirely cache, `input_tokens: 0` would be *discarded* and the previous turn's seed kept beside a full-size `cache_read`, roughly doubling the reported context — so that turn ships as ordinary input instead. Our `toAnthropicUsage` has **5 call sites** (all `message_delta` → `message_stop`, incl. the #65 policy-refusal path), which is wider and more consistent than upstream's single inlined site. ⚠ Read counters by **observed** spelling, never invented: `prompt_tokens_details.cached_tokens` *and* DeepSeek's top-level `prompt_cache_hit_tokens` (`??`, not `||` — a reported 0 has spoken), plus `cache_write_tokens` for creation (no producer on our lanes: 0 occurrences measured). Cost rides in a separate `detail` argument and is **inert today** — `cacheReadCostPer1M` has zero producers, so every discount computes to exactly 0. The OpenAI-shaped parsers both ship it — `openai-sse` (4 sites) and, since #195 (#186, closed 2026-09-21), the Codex lane `openai-responses-sse` (its six `finalUsage()` emissions share one `toAnthropicUsage` site). ⚠ `gemini-sse` and `ollama-jsonl` still seed `{input_tokens: 0, output_tokens: 0}` with no cache counters — #444.

Adding an aggregator resolver: implement `ModelCatalogResolver` in `providers/catalog-resolvers/`, register in `model-catalog-resolver.ts` — proxy-server and provider-resolver need no changes. The hosted slim catalog's `aggregators[]` field — entries of `{ provider, externalId, confidence }` — is a typed multi-provider routing index, consumed read-only; extraction, recommendations and portal live in [models-index](https://github.com/MadAppGang/models-index). ## Adapter Pipeline (v5.14.0+)

`ComposedHandler = FormatConverter (explicit adapter) + ModelTranslator (auto-selected by model id) + ProviderTransport`

- **L1 FormatConverter** (`adapters/api-format.ts`) — wire format: OpenAI, AnthropicPassthrough, Gemini, Codex, OllamaCloud, LiteLLM. Message/tool conversion in `handlers/shared/format/openai-messages.ts`, `openai-tools.ts`.
- **L2 ModelTranslator** (`adapters/model-dialect.ts`) — model dialect (context windows, thinking→reasoning_effort, vision rules): GLM, Grok, MiniMax, DeepSeek, Qwen, Codex.
- **L3 ProviderTransport** (`providers/transport/types.ts`) — auth, endpoints, headers, rate limits; aggregators (LiteLLM, OpenRouter) may override the stream format to `openai-sse`.

**Stream parser selection — 3-tier priority, in this order:**

```typescript
transport.overrideStreamFormat() ?? modelAdapter.getStreamFormat() ?? providerAdapter.getStreamFormat()
```

Parsers in `handlers/shared/stream-parsers/`: `openai-sse` (most providers), `anthropic-sse` (MiniMax/Kimi direct), `gemini-sse`, `ollama-jsonl`, `openai-responses-sse` (Codex).

- **Add a provider**: one entry in `PROVIDER_PROFILES` (`providers/provider-profiles.ts`).
- **Add a model**: a ModelTranslator adapter, registered in `adapters/dialect-manager.ts`.
- **Verify wiring**: `claudish --probe <model>` prints the full composition.

## Never-Hang Constraints (non-negotiable)

The proxy sits inside an agentic loop: whatever stalls a turn stalls the agent.

- **A restart is a stream killer, so the drain waits for a true zero first, then picks its moment.** `docker restart` cuts every in-flight SSE mid-body and each client reports `Connection lost mid-response` — that agent turn is lost. An initial 30-min measurement (2026-08-23, 906 samples) saw `activeStreams` never reach 0 (min 1; p50 5, p90 7, mean 5.1) and produced the first design — relative target, no zero wait. A ~2-day population probe (2026-08-25, 92 364 samples) corrected that window: **min 0, 4.62% of samples at zero, P(zero within 300s) = 57.5% (73.4% within 600s)** — the floor IS zero, lulls are just brief (mean 5.9s). `scripts/claudish-drain.ps1` therefore holds a true-zero wait for the first 300s (`$target` stays -1, only `activeStreams==0` fires — on the FIRST zero sample, no confirmation: confirming costs a whole lull), then falls back to the adaptive stage for the ~43% unfavorable draws: observed minimum as target, relaxed by one every 30s so the wait ends on a chosen moment rather than on the cap. Replay of the 2026-08-23 samples through the adaptive stage alone: **mean 5.19 → 3.65, worst case 10 → 6**; relaxing once per poll instead of every 30s gives the gain straight back (4.67). Budget: `$MaxWaitSec=600` (300s zero-wait + ~300s adaptive) — the 04:00 daily restart can afford 10 min. Even so, **restarting less often remains the mitigation that matters more than draining better** — `ClaudishDailyRestart` (04:00) ran the drained wrapper from 2026-08-23 (first drained restart: 08-24 04:00, logged in `~/.claudish/drain.log`), but **no scheduled daily restart is left on the fleet** — per machine: po-2023's was **disabled 2026-09-05** (user UAC), the hub po-2025's ran until **08/10** (last `daily-0400` → `OUTCOME success` 07:31 local) and was **deleted 08/10 10:09:58 local** (user UAC batch v2). The user arbitrated "no daily restart", so this is a settled decision, not an open question — settled in #280's direction 2, which also names what replaces the task: **the watchdog's proactive restart (uptime ≥ 11 h, quiet window 03:00-06:00 local, `$ProactiveRestartHours`/`$QuietHourStart` in `claudish-watchdog.ps1`) is the single nightly restart source**, so a machine with uptime to burn still restarts about once a night in practice. That de-facto nightly restart has a visible price: on 10-10 the relay po-203 (watchdog decision 01:01:05Z) and the hub po-2025 (decision 01:02:02Z, 84 s drain to zero, `docker restart` 01:03:37→01:03:47Z — hub `watchdog.log`) both restarted proactively within three minutes — scheduling coincidence, not a coordinated gesture — and the hub's stop-start interval cost 2× 502 on the WAN edge (01:03:42/46Z, attributed in #407). Both states are declared in `docs/deployment/fleet-state.md`. A `$null` count means *no signal* (proxy down, or image predates #37) and must degrade to an undrained restart, never to an unbounded wait.
- **The proxy itself never breaks a stream**, and that invariant is what makes the above diagnosable: there is no `controller.error()` anywhere in the proxy's **production** sources under `packages/cli/src` (test harnesses legitimately call it — see the filter below), and every terminating path emits `message_stop` — including `finalizeWithError` on an upstream socket death and the relay passthrough on a hub death. Corpus re-check 2026-09-20, ai-01, **1017 captured `resp-*.sse` over 10/08→19/09** (3.7× the original 277 sample): **1016 of 1016 non-empty responses carry a terminal `message_stop`** — and the 1017th is **0 bytes**, so it carries no events at all and is classifiable in neither direction. That empty-capture class is the trap, not the invariant: a `grep -L 'event: message_stop'` reports it as "1 response without a terminal event", which reads exactly like a never-hang violation. So a client-visible mid-response drop is never the stream logic; the socket died underneath it.

  ⚠ **Checking the `controller.error()` half needs a filter that drops comments *and* tests — and this paragraph's own earlier filter was insufficient.** The instrument, re-measured 2026-09-20 on `main`:

  ```bash
  grep -rn 'controller\.error(' packages/cli/src --include='*.ts' \
    | grep -v '\.test\.ts' | grep -v ':[0-9]*: *\(//\|\*\)'   # → 0
  grep -rn 'controller\.close(' packages/cli/src --include='*.ts' \
    | grep -v '\.test\.ts' | grep -v ':[0-9]*: *\(//\|\*\)'   # → 24  (positive control)
  ```

  The two weaker filters both mislead, and the numbers this paragraph used to quote have drifted while the invariant has not: a **bare** grep now returns **8**, not the "2 hits, both prose" written here earlier (3 comments — `stream-registry.ts:13`/`:91` plus `anthropic-sse-s4a.test.ts:65` — and 5 real calls); **comment-excluding alone returns 5**, every one of them in a `*.test.ts` harness that deliberately errors a `ReadableStream` to simulate a mid-stream socket death, which is *how the never-hang behavior is tested*. So a reviewer following the filter this doc prescribed got **5** and had grounds to report the invariant broken — the exact false conclusion the paragraph exists to prevent (raised against PR #166 on 2026-09-20, then refuted by re-running the same filter on `main`: identical 5, so not the PR's). **Before concluding from a count, run the same filter on the merge base** — a hit class that predates the change is not the change's. The 24 `close()` calls are the positive control: they prove the filter still matches the pattern rather than silently matching nothing. A doc that invites a check owes the check its instrument — and owes it a scope (`production sources, tests excluded`), since an unscoped number goes stale the first time a legitimate new class of hit appears.

- **`stream: false` must return a single JSON `message`, never SSE.** `/compact` is the real-world caller; SSE back to it surfaces as `"API returned an empty or malformed response (HTTP 200)"`, the session can no longer condense, and it eventually overflows and stalls. `ComposedHandler.handle()` buffers the already-translated SSE via `collectAnthropicSseToMessage()`. The trigger is exactly `payload?.stream === true` (mirrors `request-logger.ts`); anything else buffers to JSON. The collector **never throws** — a broken or empty stream degrades to a well-formed message with an empty text block.
- **A failed web search/fetch must never stop the agent** — every backend path degrades to well-formed text. No throws, no hung streams.
- **Never gzip the SSE response** — gzip buffering risks a hang. Request body only, WAN only.
- **A stream admitted with 200 that never produces a first useful event is confined, not held** — during the 14/09 deepseek-flash scheduler incident, mute-but-keep-aliving streams held hub slots ~900s each (46 streams / 19 pending at peak). `withFirstUsefulEventWatchdog` (wired in `ComposedHandler.handleStream`, all SSE formats, not ollama-jsonl) cancels the upstream after `CLAUDISH_FIRST_EVENT_TIMEOUT_MS` without a first `data:` line (default 300s, `0`=off, re-read per request — in a container that means the process re-reads its own env: a NEW value enters only at the next **recreate**, and only because compose carries the name, #310); the parser's existing synthetic finalization then ends the client turn cleanly. The window covers the FIRST useful event only — a `: keep-alive` comment or `event:` line is not one — so legitimate long thinking (whose deltas are data events) can never trip it.
- **A retried stream needs its OWN watchdog — the original wrap has already disarmed.** The wrap above clears its timer on the first `data:` line and *never rearms*; an in-stream error chunk (`data: {"error":…}`) is itself such a line, so by the time it triggers a transparent retry the protection is gone, and a bare `doFetch()` replacement would be unbounded — a mute-but-200 retry upstream then hangs the client exactly as #108 confines. `boundRetryUpstream()` (`first-event-watchdog.ts`) wraps the closure once in `handleStream`, so all three retrying lanes inherit it; non-ok/bodyless responses pass through untouched, and `ollama-jsonl` is excluded from both wraps (that wire has no `data:` lines, so wrapping it would fire on every healthy stream). Measured in review of #137: with a 1 s window in force and the wrapper removed, the client stream was still open after 6 s; with it, the turn terminates at the window. Corollary for any future recovery path: **a guard that disarms on a signal cannot protect what that same signal triggers.**
- **An upstream death before any client-visible event is recovered, not finalized (#170).** Never-hang was already satisfied by `finalizeWithError` — the turn ended cleanly — but it ended on a *notice instead of an answer*, and nothing had been forwarded that would prevent re-issuing the request. `anthropic-sse.ts` now re-forwards on both death shapes (`reader.read()` throwing, **and** a graceful `done` having emitted nothing — `docker stop` on the upstream produces the second), gated by the same predicate #65 uses for policy refusals: `!sawMessageStart && highestSeenIndex === -1 && !lastBlockOpen`. Past any of those three a replacement stream would duplicate what the client holds. Bound + kill switch: `CLAUDISH_PREVISIBLE_REFORWARD_MAX` (default 2 = the `[400, 1200]ms` ladder, `0` = off, re-read per stream), on its own counter so it composes with the policy retry without either becoming unbounded. The relay supplies the closure (it passed none before — the opts comment read `absent = inert (relay, tests)`), header-bounded and **wrapped in `boundRetryUpstream()`**: the relay bypasses `ComposedHandler`, so there is no outer watchdog to inherit and a mute-but-200 replacement would hang the client — mutation-proven, wrap removed ⇒ the stream was still open at 20 s. A re-forward is a recovery attempt, never a liveness measurement: **no `markFail`**, same separation as the #80 part 2 connect retry. Accepted knowingly: the upstream may have generated tokens that never reached us, so a re-forward can bill twice — the bound is what keeps that cheap. Driver, 2026-09-20: 13 hub container restarts in one morning (a remediation for a forwarder wedge that restarts cannot fix) cut every in-flight SSE on every relaying machine at 9-13 `activeStreams` each; **the fleet-wide turn loss came from the remediation, not the wedge.**
- **A policy refusal is retried, then surfaced labeled — never bare, never silent (#65).** `invalid_prompt`-class refusals (exact code on OpenAI-shaped wires; usage-policy message pattern on anthropic-compat wires that carry no code — Z.AI/MiniMax/Kimi) get a bounded transparent retry of the *identical* body (`[1000, 3000]ms`, max 2), fired **only while nothing client-visible exists** — stricter on `anthropic-sse`, which also requires no forwarded `message_start` since that event comes from upstream there and a retry past it would duplicate it. A persistent refusal becomes `[Upstream policy refusal — invalid_prompt: …]` + `end_turn` + `message_stop`. The classifier deliberately excludes transport errors, quota walls and rate limits, so it can never divert a subscription wall away from `isQuotaExhaustion`. `[PolicyRefusal] lane=… model=… provider=… attempt=… action=retry|surface` (forceConsole) is the countable marker for #41/#60. Before this, `openai-sse` **dropped in-stream `{"error":…}` chunks entirely** — a refusal on most providers' lane surfaced as an unexplained "empty response".
- **The failover notice never throws** — a thrown error would turn a working condensation into a failed one.
- **Strip inline `role: "system"` messages** (Claude Code v2.1.153+ injects them, e.g. system-reminders) and merge into the top-level `system` field — for `anthropic-sse` in `composed-handler.ts` and for the OpenAI path in `openai-messages.ts`. Z.AI, MiniMax and Kimi reject anything but `user`/`assistant`.

## Web Search Interception (v7.1+)

Provider web-search tool calls (`web_search`, `brave_web_search`, `tavily_search`) and GLM `<searchWeb>` tags are intercepted, never forwarded (they would fail on non-Anthropic providers).

**The decision that matters**: if the client declared a `WebSearch` tool, **remap** the call to a synthetic `WebSearch` tool_use block with `stop_reason: "tool_use"`, so Claude Code runs its own search and the loop continues. Only when WebSearch is *not* declared (sub-agents without web tools) do we suppress and inject results as a text block with `end_turn`. Suppress-and-inject in the declared case ends the assistant turn on raw search results and **stalls the agent** — the CoursIA incident, 2026-06-10. Regression: `format-translation.test.ts` ("web search remap").

**On the Z.AI wire, `server_tool_use` comes with two siblings** (live capture 2026-08-11, `regression-zai-server-tool-use-live.sse`): the tool **input arrives whole in `content_block_start`** (zero `input_json_delta` — delta-based accumulation left `rawInput` empty on every real stream), and the provider also emits a **`tool_result` block assistant-side** after executing the tool server-side. `tool_result` is user-turn-only on the Anthropic wire, so it must be suppressed exactly like `server_tool_use` (the same results arrive as the preceding text block) — and because that removes a second block, the parser must remap the following deltas/stops down or indices desync ("Content block not found"). Regression: `format-translation.test.ts` ("Chantier D", structural asserts).


**Any frame the parser drops takes its `event:` line and blank separator with it** (S4-a): an `event:` header that reaches the client without its `data:` body kills the turn with `Could not parse message into JSON` — so `event:` lines are held until the data line is adjudicated, on **both** branches (thinking filter and passthrough). The index-mapping layer (jumped starts remapped, the pair remembered so deltas/stops follow) also runs on **both** branches — MiniMax (`shouldFilterThinking()` = true) takes the filtered one — and an **orphan delta/stop** (no block the client opened at that index, e.g. MiniMax-M3's implicit signature block: `signature_delta` + stop at 0 with no `content_block_start`) is **dropped whole**, never re-attached. Synthetic tails (`finalizeWithError`, empty-stream finalization) are built with `JSON.stringify` — never string interpolation of the model name — preserve an upstream-reported `stop_reason`, and never emit a second terminal pair after a real `message_stop`. Production fixtures + pins: `anthropic-sse-s4a.test.ts` (`minimax-m3-anthropic-implicit-signature-r10324/r10416.sse`).

Backends, first usable result wins: MCP `searxng_web_search` (`SEARXNG_MCP_URL`, ≥ 5s) → direct HTTP `{SEARXNG_URL}/search?format=json` (**2 attempts inside an 8s total budget, 5s/attempt** — dimensioned from measured p50 0.92s / p95 2.97s, roo-extensions #3388; `SEARXNG_ATTEMPT_TIMEOUT_MS` overrides) → error text; fetch adds an `r.jina.ai` retry for bot-hostile hosts and a 500KB cap. Every call is deadline-bounded, and direct-HTTP attempt durations feed a rolling 50-sample p50/p95 log (`[WebSearch] latency window: …`) for drift detection. **Basic-auth credentials belong in the `SEARXNG_URL` userinfo** (`https://user:pass@host`, standard curl form): `searxngConfig()` parses them into an `Authorization: Basic` header and strips them from the logged base URL. `search.myia.io` sits behind IIS Basic Auth since 2026-08-19, so credential-less WAN clients get 401; LAN deployments reach the backend directly and send no header. `MCP_AUTH` / `SEARXNG_MCP_TOKEN` are provisioned via RooSync — never hardcode. When `SEARXNG_MCP_URL` is unset the MCP layer is skipped entirely (zero behavior change). Detail: `docs/reference/web-search-interception.md`.

## Relay / Sidecar Mode (v7.2+)

One binary, three modes, selected by `CLAUDISH_RELAY_UPSTREAM`. Each machine runs its own container so the hub stops being a single point of failure.

| `CLAUDISH_RELAY_UPSTREAM` | Mode | Behavior |
| --- | --- | --- |
| **unset** | **HUB** (po-2023) | Always local. Zero change vs. before. |
| set + hub **alive** | **NOMINAL relay** | Forwards the raw request to the hub; response repiped through the never-hang passthrough. **No local capture** (hub captures centrally). |
| set + hub **dead** (hysteresis) | **AUTONOMOUS** | Falls through to the normal local pipeline + local capture. |

Gotchas:

- **The cluster key is injected as `x-proxy-key`, NOT `x-api-key`**, and the client `authorization` is kept. `x-api-key` arms `NativeHandler`'s proxyKey→Anthropic swap, which strips auth → **401**. `X-Claudish-Machine` must survive the hop or central attribution is lost. Since #282 the native lane **strips `x-proxy-key` and every `x-claudish-*` header before api.anthropic.com** (`stripProxyOwnHeaders`, shared by `NativeHandler.handle` and the native `count_tokens` path) — the key swap READ `x-proxy-key` without removing it, and the passthrough sent the cluster credential to the Anthropic upstream on every native request (measured 2026-09-29; ignoring is not stripping). Since #289 the **vision fallback** (image descriptions `ComposedHandler` asks of `services/vision-proxy.ts` on non-vision models) is the third site: `sanitizeVisionAuthHeaders` runs the same strip AND the same proxy-key→stored-key swap (oat → `authorization: Bearer`, else `x-api-key`; policy injected by proxy-server via `setVisionAuthPolicy`) — the path used to forward the inbound `x-api-key` verbatim to `api.anthropic.com/v1/messages`. Since #315 a non-matching key ALSO crosses the shape gate before that call: only an `sk-ant-` key leaves (`stripForeignVisionApiKey` on the extracted `isAnthropicShapedCredential` — one predicate shared by the native refusal #296 B, the mixed strip #305 and the vision drop, so the sites cannot drift); a foreign key is dropped and the description call degrades like the pre-existing missing-credential case (401 → null → images stripped, turn continues), under the SAME kill switch as the native guard (`CLAUDISH_NATIVE_FOREIGN_TOKEN_GUARD=0`, one switch one policy).
- **Loop topology is detected by identity, on two planes (#156/#279).** `/health` publishes a per-process `instanceId` (random, derived from nothing); `heartbeat()` comparing the upstream's id to its own catches a node forwarding to ITSELF whatever the URL (the 2026-09-19 ARR-loop shape — one forceConsole marker, heartbeat counts failed, hysteresis settles AUTONOMOUS stable instead of flapping). What the heartbeat CANNOT see — the optimistic boot window before the first tick, and A→B→A cycles (each node's /health is answered by the other) — the request itself witnesses: every forward appends the sender's id to the `x-claudish-hops` header, and a node finding its own id in the list it received serves locally with one marker, never a refusal. The hop append must never touch `authorization` / `x-proxy-key` / `X-Claudish-Machine`.
- **Hysteresis is asymmetric on purpose**: 2 consecutive `/health` failures → AUTONOMOUS (fast failover); recovery needs 3 OK heartbeats **+ 60s cooldown + a deep tool-call probe** (`glm-5.3` — the current sonnet nominal — must reach `message_stop`). Anti-flap.
- **`CLAUDISH_NO_ANTHROPIC=1` on every machine except ai-01** — reroutes bare native targets to the budget `modelMap.sonnet` instead of `api.anthropic.com`. Defense in depth, not the primary policy.
- **`CLAUDISH_HOST_PORT` is load-bearing, not cosmetic**: port 3000 is already taken on some hosts (ai-01), so a hardcoded binding makes `docker compose up` fail outright. The container side always stays 3000.
- **Two capture variables, one letter apart in meaning and deliberately not in spelling**: `CLAUDISH_CAPTURE_HOST_DIR` (host bind path) vs `CLAUDISH_CAPTURE_DIR` (in-container path, **empty = write nothing**). Keep capture **on** for sidecars: a forwarded request writes nothing, so any file that appears IS a forward-path outage capture — the trail `reconcile-outage-captures.ps1` needs. But **capture files are not a count of mode switches**: capture follows *local serving*, and a request served locally because its own forward failed (`header-timeout after <budget>ms` — see `CLAUDISH_RELAY_HEADER_TIMEOUT_MS`, default 360s since #320, relay still NOMINAL) captures just as an AUTONOMOUS one does. Measured on po-203, 2026-09-13: **68 loose files over 2h20 against a single 71s AUTONOMOUS episode in the surrounding 28h** — reading files as mode switches over-counts by ~30×. The `-direct` / `-openai` field in the filename is the handler label, not the mode. Disabling capture is a disk-starvation escape hatch that silently destroys that trail.
- **An armed cascade is always hand-added, so it can live only in the container record (#141, fixed).** `install-sidecar.ps1` generates the per-machine `.env` with exactly `CLAUDISH_PROXY_KEY` / `CLAUDISH_RELAY_UPSTREAM` / `CLAUDISH_CONFIG_DIR` / `CLAUDISH_CAPTURE_HOST_DIR` / `CLAUDISH_HOST_PORT` / `CLAUDISH_CONTAINER_NAME` (+ optional `COMPRESS`/`NO_ANTHROPIC`/`CAPTURE_DIR=`) and **never a single `CLAUDISH_FAILOVER_*`** — arming is a provisioning act, not an install one. Until #141 the rewrite also **dropped** any that were there, so an armed state survived on `unless-stopped` luck alone; since #141 the installer carries runtime-policy lines over verbatim, **exits non-zero before writing** an `.env` that would gut a live armed cascade (`claudish-drain.ps1 -Recreate` refuses the same condition), and `-RebuildEnvFromContainer` recovers a state that exists only in the container. The 07/09 hub wipe was therefore not an operator slip but the tool's default outcome — the hub only survives because po-2025 maintains `D:\claudish-shadow\.env` by hand, and that file carries **17 armed** of the 23. **Before any sidecar recreate: diff the target env file against `docker inspect`'s `.Config.Env` on NON-EMPTY assignments, and reconstruct the file first** (its output carries `CLAUDISH_PROXY_KEY` — local file only, never committed, never printed). ⚠ **Diff by value, not by name**: every container shows all 23 names whatever its state, so a name diff answers a different question than the one asked — it was wrong about ai-01 (reported armed, actually **0 non-empty**, 2026-09-19), and it is what makes a partially-filled file deceptive (po-203: 16 lines in the file look recreatable, and whether the 7 absent names matter depends entirely on whether they hold values). `install-sidecar.ps1 -RebuildEnvFromContainer` does this correctly and is the tool to use rather than a hand-rolled grep.
- **The relay branch must stay before `interceptWebTools` / `getHandlerForRequest` / `logRequest`** in the `/v1/messages` route — that ordering is what makes capture mode-aware for free.
- **A forward connect failure gets exactly one retry (+250 ms) before falling through (#80 part 2)** — the container → `host.docker.internal` tunnel resets chronically (~1 per 8 min measured over 12 h, 87 failures). A connect failure fails in milliseconds, so the retry absorbs the blip at no perceptible cost, and an **absorbed retry does not `markFail`** — the chronic blips no longer feed the AUTONOMOUS hysteresis nor divert requests to the local cascades (invisible to the central capture, and potentially PAYG where the hub's subscriptions would have served). A header deadline is never retried (that would double the budgeted stall), nor is an HTTP 5xx (the hub answered; hysteresis owns it). `[Relay] forward connect failed (…) — retrying 1/1` is the countable marker.
- ⚠ **Two upstream failure signatures — only one is a client-side transport artifact.** A **connect** failure (fails in ms, absorbed by the +250 ms retry above) is client-side transport **only under #80's precondition — the hub independently reachable at the same moment**; a refusal with the hub down is the hub, not the transport. **TCP accepted with an invalid response** is *hub-end unavailability on that window*, and it **is client-visible on the WAN entry** — generalising the #80 sentence to every relay flap is how the fleet ledger kept writing *"impact client nul"* beside episodes that cost real client requests. A flap reads hub *reachability from the relay*, never cause location. Count WAN client impact from the **ingress IIS log** (`W3SVC49`, status/substatus/win32 columns — its own ingress only), **never from the relay's own tally** — its 2-consecutive-failure heartbeat is blind to single-minute blips. Evidence and day-scale correlation — the 08:50:56Z replacement is **corroborated hub-side and attributed to a Docker Desktop engine recovery** (same container id restarted, no `create` in the window; the earlier `com.docker.compose.replace` hypothesis is refuted; #419 reconciled 10/10): `docs/reference/relay-internals.md` § *The two upstream failure signatures*.
- **`hub HTTP 500` is the *relay's* reading, and until #212 the hub could not corroborate it — read the hub's own stall signature before hunting a provider.** `relay.ts` maps `res.status >= 500` to `markFail(forward-http-${status})` and so arms the AUTONOMOUS hysteresis on the status alone, whatever produced it — with **two carve-outs, both pass-throughs because in both the hub answered and is alive**: a relayed **529** (a provider's overload, #299 A) and a **503 marked `x-claudish-drain-freeze: 1`** (the hub's own drain window, #318) reach the client with no `markFail` and no local replay; every other 5xx, and an unmarked 503, keeps the fallthrough. The same rebuild now also relays `retry-after` on **every** non-streaming error (a hub-relayed 429 reaches the client with its `Retry-After`, which Claude Code honors) and re-emits the drain-freeze marker so the pass-through composes across A→B→hub chains. Measured 2026-09-22 `03:18:02→03:19:48Z` (hub po-2025, 106 s): **18 requests across 6 machines (po-2023…po-2027, ai-01) and 4 models** got no response at all, the hub logged **nothing** for any of them — no `[ttft]`, so no upstream was ever reached — while its per-minute throughput collapsed `32 → 4 → 1 → 24`. Two exclusions to reuse rather than re-derive: the compaction (its `compaction.log` is **UTC**: `01:50:15Z→02:43:22Z`, ended **35 min before**) and the drained restart (`02:03:01Z`, **1h15 before**, 0 streams cut). The decisive evidence was the **host's** log, not the proxy's: `Tcpip` **4231 ephemeral-port exhaustion** (1×/day on 4 of the last 7 days, dynamic range at the Windows default 16384, `TcpTimedWaitDelay` unset) and `DNS-Client` **1014**. The general instrument rule this leaves behind: the hub's `/v1/messages` and `/count_tokens` 500 branches logged through `log()` — **file-only, a no-op with debug off, which is how a hub runs** — so *an empty hub log was never evidence of a healthy hub*; since #212 both branches emit `[Proxy] ERROR 500 on POST <path>` via `logStderr`.

Tests: `relay.test.ts` (**45 as of 2026-09-20** — hysteresis, header build incl. ai-01 Opus passthrough, gzip, never-hang delegation, pre-visible re-forward; the "16" written here previously had drifted to 40 before #170 added 5, so treat a bare count as dated or don't write one). ## Budget Failover (v7.2+)

Substitutes the *model itself* for a whole **role** (`opus`/`sonnet`/`haiku`/`fable`) when that role's metered plan is exhausted — a subscription concern, distinct from `FallbackHandler`, which swaps *providers* for the same model (a transport concern). They compose. Every substitution is **announced**, because silent degradation leaves the agent assuming capabilities it lost (or missing ones it gained).

**Three notice moments, two channels**, centralized in `applyFailoverNotices` so `ComposedHandler` *and* `NativeHandler` are covered: at **condensation** (appended to the `/compact` message — the one moment context is rebuilt anyway — naming the currently-resolved step and its depth); at the **moment of failover** (prepended as stream content block 0, every real block's `index` shifted `+1`, re-fired when the resolved step changes mid-session); and on **recovery** (symmetric, so the model recalibrates after the nominal returns). None of the three may throw — a missing notice beats a broken stream, and a thrown error would turn a working condensation into a failed one.

> ⚠ **Notices state facts, never instructions — doctrine 2026-08-23.** The recovery notice originally told the agent to "resume your normal capability and **risk appetite**" and to "clean up any over-conservative decisions made under the substitute". Arriving unexplained in content block 0, that was indistinguishable from a prompt injection: it was reported as one on 2026-08-23 by a fleet agent whose security reflex fired correctly, before being traced back to our own code. Rewritten factual in #126 ("Capability note: …", plus a "Remaining fallbacks: …" depth enumeration after the step being served). Standing rule for any new notice: which role, which model, which direction — state capability or scope, never risk posture, and never ask an agent to undo decisions it already made.

**A role's failover is an ordered list of steps, not a single target.** `CLAUDISH_FAILOVER_<ROLE>` is `>`-separated: step 0 serves when the nominal walls, step 1 when step 0 *also* walls, and so on; the last step is typically PAYG, which has no weekly wall. Opus→GLM is not a special route — it is Opus→Qwen with Qwen also dead, falling through to Qwen's own successor. GLM is a **rolling ~5h window** (it dies *and* restarts every 5h, unlike Qwen's consumable weekly pool), so PAYG naturally fills GLM's holes with no extra routing.

**A wall is keyed by provider BUCKET, never by role (#275).** The arm used to exile every request of a role on any member's refusal; since #275 a qualifying refusal while serving the nominal walls `bucket(nominal)`, and only requests whose own resolved nominal sits in a walled bucket divert to *their* role's cascade. Contagion is provider-scoped and nothing else: the OpenAI Pro plan exhausting walls `openai-codex` (Sol AND astra divert, across roles); the GLM Coding 5h window walls `glm-coding`; a sonnet-role Sol wall never touches a sonnet request served by a healthy GLM nominal. The request-side derivation is `classifyNominalBucket` (`fork/failover.ts`) — it mirrors step 2c's guard exactly: explicit targets bucket on their CANONICAL provider name (`parseModelSpec` resolves shortcuts, so `gc@glm-5.3` and bare `glm-5.3` — whose `route()` primary is `glm-coding` — converge on one bucket); a bare `claude-*` (or any unmapped bare name, absent a user routing override) NEVER consults `route()` — under a hub with no Anthropic key the chain's answer would be `openrouter`, mis-bucketing the native lane — and takes a **per-model** native bucket (`anthropic-native/<model>`): the native meter is the *client's* credential, so a native sonnet 429 must never exile native opus. Config-arms (`CLAUDISH_FAILOVER_ACTIVE`) still divert the whole role regardless of bucket, and `armFailover(role, reason)` without a bucket keeps the legacy role-wide `*` wall.

**A cascade step can delegate to another ROLE — `role:<r>` (#274).** It resolves to the target role's NOMINAL when that bucket is healthy, else to the target's currently-resolved step (shared walk state) — e.g. `CLAUDISH_FAILOVER_OPUS=cx@gpt-6-sol>role:sonnet`. Invariants: a role's own nominal NEVER appears in its cascade; the delegation graph is proven **acyclic at load** (a cycle is refused with a loud log, never a runtime loop); dwell pins and notices name the CONCRETE resolved step, never the role reference, and a pinned delegation step HOLDS while the delegation resolves (a `wasNominal` yield that un-pinned whole sessions was removed in review 01/10 — do not reintroduce it); bookkeeping runs on both levels exactly once, the owner's coordinate DERIVED from the resolution (`resolveDelegationOwner`), never from a reverse target→step lookup, which finds the delegating step. Nominal resolver unset (tests) ⇒ a role-step falls to the target's own cascade, or is skipped — never a placeholder. **#331: a `role:` step's per-step backoff binds only the CONCRETE it was recorded against** (`StepFailure.concrete`, threaded from `delegation.concrete` at every mark) — the TTL freezes the step only while the delegation keeps resolving to that same concrete, at BOTH walks (armed `resolveSkippingFailed` AND the one-shot overload walk `resolveTransientStep`), the dwell pin's servable test and the last-step fallback (where a frozen-on-current-concrete role-step surfaces the refusal instead of re-paying it — the anti-408 half; measured: `haiku[1]`=`role:sonnet` at 408 walls/24 h TTL while sonnet served). The #263 revisit guard is keyed by the concrete PAID (`triedConcretes`), not the step index — a delegation that advanced mid-request serves a different concrete, not a re-payment. A record without a concrete binds (conservative); a #261 closure binds regardless. Pins T1-T6 + routes R1/W17/V1: same files. Record: `docs/reference/budget-failover.md` §Role delegation.

Env, read at proxy startup (canonical annotated template: `.env.sidecar.example`): `CLAUDISH_FAILOVER_<ROLE>` (the `>`-separated cascade), `..._LABEL`, `..._DIRECTION` (`degraded` default · `improved` · `lateral`), `..._NOTE`, `..._RESET` (operator-declared wall-lift per step, ISO 8601), `CLAUDISH_FAILOVER_ROLE_MODELS` (aliases so clients naming the nominal model directly still get cascade protection), `CLAUDISH_FAILOVER_ACTIVE`, `CLAUDISH_FAILOVER_AUTO`, and the #91 grace-before-arming knobs `CLAUDISH_FAILOVER_ARM_AFTER` (consecutive qualifying nominal refusals before arming; 1 restores arm-on-first-refusal) · `CLAUDISH_FAILOVER_ARM_GRACE_MS` (wait-and-retry the nominal once in-request) · `CLAUDISH_FAILOVER_ARM_RETRY_AFTER_CEILING_MS` (a 429 naming a retry-after below this is a burst and never arms — a wall speaks in hours) · `CLAUDISH_FAILOVER_SESSION_DWELL_MS` (minimum time a session keeps its resolved step; see the dwell bullet below) · `CLAUDISH_FAILOVER_RECOVERY_GRACE_MS` (how long a verified nominal recovery must hold before dwell pins yield back to it; see the dwell bullet below). All `>`-separated fields are position-preserving against the step list. ⚠ **In a compose-deployed container the environment is fixed at create time: a name absent from `docker-compose.yml`'s `environment:` list NEVER reaches the process** — the env file only interpolates names that list carries. #304 measured exactly this failure: the five #91/#293 knobs above plus `CLAUDISH_NATIVE_MODEL_PIN` shipped documented (`.env.sidecar.example`) but unreachable in every compose deployment. `packages/cli/src/test-support/compose-env-coverage.test.ts` now cross-checks code↔compose in both directions (every name the code reads must be injected; every failover entry must be read) with positive controls. Consequence for "re-read per request" flags (`*_THINKING`, per-request kill switches): they mean no proxy restart — but in a container a NEW value still enters the environment only at the next **recreate**. These failover knobs are startup reads (`initFailover`) anyway.

- **With nothing set every code path is inert.** Configuring a target does **not** activate it — arming is separate and deliberate.
- **Unset `_DIRECTION` means degraded** — never flatter the substitute.
- **`isQuotaExhaustion` is deliberately narrower than `FallbackHandler.isRetryableError`**: 402 arms on status alone; 429 arms *only* when the body names a quota/credit/balance/weekly/plan wall — a per-minute burst must not burn the weekly switch. **401 and 404 never arm**: those are wiring mistakes, and swapping the model would hide a bad key or bad model id behind a plausible-looking answer.
- **`resolveFailoverTarget(role)` is the single resolution path** — used by both the swap in `getHandlerForRequest` and the `handleWithCascade` loop. The loop never passes an override target in; it mutates failover state and the next iteration re-reads. No double resolution.
- **`handleWithCascade` is bounded, never `while(true)`**: nominal → step 0 → step 1 → …, capped at `steps.length + 1` attempts. The **c-reuse invariant** is load-bearing — a handler must not mutate the Hono `Context` before returning a non-ok `Response`, or re-calling `handler.handle()` across iterations breaks.
- **Per-step backoff `[10m, 30m, 1h, 4h, 24h]`, and a known reset time overrides it** (`..._RESET`, or a date parsed from the body — Qwen names its reset, MiniMax counts down). ⚠ **A `..._RESET` in the future is a CLOSURE (#261)**: it closes a HEALTHY step outright (never selected, never the last-step fallback, a dwell pin on it yields), and `initFailover` logs one `[Failover] CLOSED <role>[<i>] … until <date>` per closed step — so before any deploy, read the `_RESET` values **by value** and list every future date with the step it will close. A step that HAS failed follows its failure record's date (body-parsed wins). `stepFailures` survives the bucket-wall TTL cycle (else a weekly-walled step is re-probed every 10 min) and is cleared only when the nominal recovers AND no wall remains anywhere (#275 probe-storm guard). Record: `docs/reference/budget-failover.md` §Per-step backoff.
- **The bucket-wall TTL itself grows while the wall holds (10 m → 20 m → 40 m, capped), per bucket** — a flat 10-minute disarm/re-arm oscillated for the whole duration of a wall: ~6 provider switches per hour, each flipping the serving model twice with a cold prompt-cache at both ends (measured on the hub: 107 arms ≈ 214 model transitions per 24 h, #91). Each TTL expiry that re-arms escalates the next arm's TTL; any nominal success on that bucket resets it (fresh episode); a re-arm more than 40 min after the last disarm starts back at base. `[Failover] ARMED bucket <bucket> (<role> nominal) …` / `… (ttl Nmin, escalated)` and `DISARMED bucket <bucket> → probing nominals … next arm TTL grows to Nmin` keep the hub log countable (#91 point 3).
- **A session keeps its resolved step for a minimum dwell** (`CLAUDISH_FAILOVER_SESSION_DWELL_MS`, default 10 min, `0` = off; sliding — every request renews it). `resolveFailoverTargetForSession` pins the session: the pin **holds** through role-level churn (disarm → probe → re-arm moves traffic only *between* conversations) and **yields** when the pinned step itself TTL-fails. Nominal is never pinned. The pin also **yields on VERIFIED nominal recovery**: the FIRST nominal success since the last arm, stamped only while no wall is live, held `CLAUDISH_FAILOVER_RECOVERY_GRACE_MS` (default 2 min), keyed role|bucket so a sibling bucket's recovery never un-pins (stamping every success holds pins forever; stamping under a live wall mass-un-pins at its expiry — both caught by coordinator probes, 01/10). Marker: `[Failover] DWELL <role> session …<id> yielded — nominal recovered Ns ago`. Record: `docs/reference/budget-failover.md` §Session dwell.
- **A NON-quota death of the pinned step forfeits the dwell instead of re-pinning the successor (#276).** `markStepFailed(..., { nonQuota: true })` — set only at the step-advance site — makes the pin yield with **no re-pin**, under a one-dwell-window tombstone that also covers the sibling resolution of the same cascade attempt (the loop resolves twice per attempt; without the tombstone the second resolution re-pins in-request). Without it, a content-filter 400 on step 2 re-pinned a session at the PAYG tail for hours while the nominal sat healthy (hub, 2026-09-28). A resolution landing on the nominal clears the tombstone. Marker: `… died non-quota; dwell forfeited, re-resolving unpinned`. Pins: `proxy-server-nonquota-unpin-route.test.ts`, `failover.test.ts` (#276). Record: `docs/reference/budget-failover.md` §Non-quota death forfeits the dwell.
- **A nominal's transient OVERLOAD walks the cascade once, writing no failure state (#299-B).** `isOverloadWalkClass` (529; a 429/503 the patient backoff already exhausted into a 529; `400 connection_error`) — deliberately NOT folded into `isTransientOverload`, which gates the ~5-min patient backoff — makes `handleWithCascade` try the FIRST SERVABLE step once, picked read-only by `resolveTransientStep` (skips TTL-failed steps, walled buckets and unresolvable role-steps; none ⇒ surface the original). Through `forceTarget`: **no arm, no stepFailures mark, no bucket wall, no dwell pin** (success bookkeeping is still mirrored). Native lane excluded (the client's own credential; substitutions are announced). A step that fails **or throws** surfaces the ORIGINAL overload — the catch is load-bearing: without it the client gets a terminal 400 instead of a retryable 529. Marker `[Failover] WALK <role> one-shot …` (stdout). **#348**: the walk is skipped — one `WALK <role> skipped — budget Nms > Mms` marker — when the nominal already spent `CLAUDISH_FAILOVER_WALK_BUDGET_MS` (default 300 s, `0` = off, per request); **at that default the 429/503 walk class NEVER fires** (it arrives at ≈365 s, past the budget, for every client — only the direct-529 and `400 connection_error` classes ever walk). No client-gone skip exists — a client abort is undetectable pre-write on this stack (W16 pins the negative result); bare step targets are bucketed canonically as THEMSELVES (`concreteStepBucketOf` — a role-keyworded step id must not re-map onto the nominal's bucket, W19) with the nominal's own bucket skipped. The probe matrix, the canonical-bucketer rationale and the armed-walk asymmetry: `docs/reference/budget-failover.md` §One-shot. Pins W1-W4/W7-W19 + P1-P6: `proxy-server-overload-walk-route.test.ts`. Record: `docs/reference/budget-failover.md` §One-shot overload walk.
- **A failover target must resolve on the machine that calls the models** — a sidecar pointed at a custom endpoint defined only in the hub's `config.json` fails exactly when it is needed. **Arm the cascade on sidecars too**: AUTONOMOUS is rare but is exactly when the hub cannot help (ai-01 sidecar, 20-25/08: 54 of 124 locally served requests failed on `HTTP 429 [GLM Coding]` with nowhere to fall — the worst window, not a current rate). ⚠ **Count armed state by VALUE** — `grep -cE '^CLAUDISH_FAILOVER_[A-Z0-9_]+=.+'` — never by name: compose injects every name with a `${VAR:-}` default, so all containers show all of them (a 2026-09-18 "ai-01 is armed" claim was that miscount; it holds 0 non-empty). And `roleFromModelName()` matches only `opus|sonnet|haiku|fable`: a client naming a bare provider id resolves to `null` and the cascade stays blind — set `CLAUDISH_FAILOVER_ROLE_MODELS`. Record: `docs/reference/budget-failover.md` §Failover targets on sidecars.
- **A cascade step that cannot take THIS request skips forward (#431)** — context overflow (vLLM refuses `prompt + max_tokens > max_model_len`, never trims; the recovery turn is HTTP 200, which the loop used to read as success and hand back as the answer — on `/compact` it would have been the session's *summary*) or a saturated endpoint limiter (unbounded FIFO). The signal is the `x-claudish-step-skip` response header (`context`/`busy`), set by ComposedHandler, acted on ONLY for a non-last step: advance with **no markStepFailed, no wall, no arm** — the step is healthy, the request does not fit — and the dwell pin on the skipped step yields for that request (re-pins at the successor). The skipped index is excluded from BOTH resolutions of every later attempt (swap + loop read run twice per attempt). Marker `[Failover] SKIP <role>[<i>] reason=context|busy …` (forceConsole). **AC2**: `customEndpoints.maxOutputTokens` clamps `max_tokens` down pre-conversion (one seam covers openai + anthropic wires). **AC3**: `CLAUDISH_FAILOVER_STEP_BUSY_WAIT_MS` (default 2000, `0` = off, per request) bounds ONLY step attempts — the loop marks the request Context, the nominal keeps its unbounded FIFO; a timed-out waiter removes its own resolver from the FIFO or the slot leaks. Kill switch `CLAUDISH_FAILOVER_STEP_SKIP=0` restores the pre-#431 behavior. Pins K1-K11 + 5 mutations: `proxy-server-step-skip-route.test.ts`. Record: `docs/reference/budget-failover.md` §Step skip.

### `CLAUDISH_QWEN_THINKING`

`disabled` (default) · `passthrough` · `budget:<n>`. **Unset is not neutral** — Qwen reasons by default, so unset means "think, at length", and the Token Plan bills on **output**. Re-read on **every request**, deliberately: the fleet flips this during a budget crunch, and a cached value would require restarting the proxy that is at that moment keeping everyone working.

**Two switches on two wires, and each endpoint ignores the other's form**: the OpenAI-compatible endpoint takes `enable_thinking` + `thinking_budget`, the Anthropic-compatible one takes the native `thinking` object. `QwenModelDialect.prepareRequest` branches on `ctx.wireFormat`; converting unconditionally (the old behavior) **deleted the only switch that works** on the Anthropic wire. Post-deploy check: on prompt `"Reponds exactement: ok"`, `input_tokens` dropping 67 → 31 proves the native switch reached Qwen. Full measurements: `docs/reference/budget-failover.md`.

### `CLAUDISH_GLM_THINKING`

`passthrough` (default) · `disabled`. GLM's switch is **binary** on the OpenAI wire (`thinking: {"type":"enabled"|"disabled"}`) — no budget control, unlike Qwen. Re-read on every request, same crunch-flip rationale.

**GLM thought by default and had no off switch at all**: `GLMModelDialect` deleted `thinking` unconditionally (a GLM-4.x-era artifact) and the OpenAI `buildPayload` never emitted the field either, so the client's ask was inert in both directions. Probed 2026-08-20 against the `gc@` Coding Plan (`glm-5.3`, prompt `"Reponds exactement: ok"`): field absent → 37 output tokens / 131 reasoning chars; `{"type":"disabled"}` → **3 tokens, 0 reasoning**; `budget_tokens` tolerated and **ignored**. `passthrough` preserves today's effective behavior; the `zai@` anthropic wire is unprobed, so only an explicit `disabled` sets the field there.

## OpenAI-Compatible Ingress (v7.2+)

`/v1/messages` is the **native** ingress; `POST /v1/chat/completions` is a **translated** one — converted to Anthropic shape, run through the **same** `getHandlerForRequest` → `ComposedHandler.handle` pipeline, then translated back. An OpenAI client (sk-agent, any `AsyncOpenAI` consumer) therefore inherits the routing cascade, budget failover, accounting and leak policy for free, by changing `base_url` alone.

- **Never-hang holds here too**: a malformed stream degrades to a single terminal chunk + `data: [DONE]`. `thinking` blocks surface as `reasoning_content`; `stop_reason` maps to `finish_reason`.
- **Request-side thinking controls are mapped (#435)** — `enable_thinking` (top level or under `chat_template_kwargs`) and `reasoning_effort` land on the house `thinking` object: `false` → `{type:"disabled"}`, `true` → enabled with a 2048 default budget, effort → the inverse of `openai-api-format`'s budget ladder (2000/8000/24000/32000). An enabled block is always legal (≥1024, `< max_tokens`): against a client-sent `max_tokens` it clamps; against our own 4096 placeholder it *raises* the placeholder — clamping "high" to 4095 would invert the ask to "minimal" downstream. Same fix closes the Qwen openai-wire passthrough, which mapped *any* `originalRequest.thinking` to `enable_thinking: true` — the exact inversion of a disabled ask. Measured end-to-end on gc@glm-5.3 via the hub (2026-10-11): 36→3 completion tokens, reasoning gone.
- **A failover notice never rides the content here (#229)** — it arrives in the `x-claudish-failover-notice` response header (base64 of the UTF-8 text), on both the streaming and JSON responses, and the relay passes it through. `/v1/messages` keeps the in-content block 0 for the Claude Code agent loop. The gate is the route (`noticePolicyForIngress`), never a user-agent: a programmatic consumer reading a notice as its answer is how an empty model output passed a code review on 2026-09-23.
- **The relay is path-aware** — a sidecar forwards to the *same* route the client hit, so an OpenAI request reaches the hub's `/v1/chat/completions` in NOMINAL mode and the resilience model is preserved. The deep liveness probe stays on `/v1/messages`.
- Out of scope for now: `/v1/models` discovery, OpenAI web-search interception, per-role thinking policy on this path. Detail: `docs/reference/openai-ingress.md`.

The turn shares ONE deadline across all its header legs (initial attempt, connect retry, #170 re-forwards — 3 × 360s would exceed the client's 10-min timeout), and the NOMINAL→AUTONOMOUS flip aborts in-flight header waits with the `aborted-on-autonomous` fallthrough label (a wedged-but-answering hub is detected in ~200s by the stall detector; without the abort, every forward dispatched in that window would sit out the full 360s). A relay's flap rate still tracks **hub reachability**, and remains a hub-load signal before it is a sidecar problem.
- **Policy: Anthropic-billed models (Opus, Fable, Sonnet) must come from `myia-ai-01` only.** Verdicts: `[OK]` ai-01 · `[REVIEW]` po-2025, which may run an authorized Safari/agent-sdk workflow — **confirm with the user before calling it a leak** (2026-06-21: six false WARNs were raised by skipping that step) · `[LEAK]` any other machine.
- **`cc_is_subagent=true` is the leak signature, and it lives in the request body, not stdout** — `docker logs` alone cannot see it; inspect a capture. The `[LEAK-SUBAGENT]` (rogue Opus sub-agent, exit 1) vs `[REVIEW-INTERACTIVE]` (user driving their own session, exit 0) split is what stops the tool crying wolf on legitimate dev sessions.
- **A confirmed sub-agent leak is fixed client-side** — a `~/.claude/rules/` rule pinning `model: "sonnet"` on spawns, reserving Opus for genuinely complex tasks. Not fixable in the proxy.

Capture format, archive/GDrive retention, device-id attribution, exact commands: `docs/reference/traffic-analysis.md`.

## Channel Mode (MCP, v6.4.0+)

Async model sessions with push notifications, built on the low-level `Server` class declaring `experimental: { 'claude/channel': {} }`. 11 tools, gated by `CLAUDISH_MCP_TOOLS` (`all` default · `low-level` · `agentic` · `channel`). The wire contract is pinned by `channel-wire-format.test.ts`.

- **`meta` keys must match `[a-zA-Z0-9_]+`** — Claude Code **silently drops** keys with hyphens or other characters. Keep new `extraMeta` keys underscore-only.
- **Emitting a correct frame is not enough.** Rendering is gated client-side: CC ≥ v2.1.80; Anthropic auth via claude.ai or Console key (not Bedrock/Vertex/Foundry); an **interactive** session (in `-p` mode registration never runs and frames are silently dropped); the server declared in `.mcp.json` / `~/.claude.json` (**`--mcp-config` is not consulted by the channel resolver**); and the server **named in `--channels`** or `--dangerously-load-development-channels`.
- `CLAUDISH_CHANNEL_TRACE=1` (+ `CLAUDISH_CHANNEL_TRACE_FILE` when the host swallows stderr) traces producer → bridge → wire, so a server-side drop is distinguishable from client-side gating. Off by default, zero production overhead.

Full contract, launch commands, diagnostic scripts: `docs/reference/channel-mode.md`. Tests: `bun test --cwd . ./packages/cli/src/channel/*.test.ts` (65 across 5 files).

## Debugging & Tests

Failed-translation workflow: `claudish --model X --debug "say hello"` → `claudish --probe X` (verify the composition) → `/debug-logs logs/claudish_*.log` (diagnoses the failure mode, extracts SSE fixtures, writes a regression test) → `bun test packages/cli/src/format-translation.test.ts`. Manual extraction: `bun run packages/cli/src/test-fixtures/extract-sse-from-log.ts logs/claudish_*.log`.

**Keep debug logs verbose** — empty chunks and raw deltas included; that is what makes real model streaming behavior legible. Suppress noise at the registration/initialization level (e.g. conditional middleware), **never at the streaming-data level**. Under `--debug` both parsers emit greppable `[SSE:openai]` / `[SSE:anthropic]` lines, which become test fixtures.

`format-translation.test.ts` replays `.sse` fixtures from `test-fixtures/sse-responses/` through the stream parser. Helpers: `parseClaudeSseStream()`, `extractText()`, `extractToolNames()`, `extractStopReason()`, `fixtureToResponse()`. Add regressions as a `describe("Regression: <model>")` block (template at the bottom of the file).

**`bun run test:strict` (#175) is how a review gets an opposable verdict from a noisy suite.** The systematic failing population is machine-dependent (PATH corruption left by earlier files, `mock.module` leakage, live endpoints, real defects) — its live count lives in each machine's gitignored `.test-strict-baseline.json`, never in this file (a derived count here has drifted on every capture since). The strict runner executes the suite **bounded and scoped to `packages/cli/src`** (`--timeout 15000` per test + a 420 s wall-clock kill, because bun's timeout covers tests, not hooks — an unbounded run looped >35 min on 2026-09-29; a bare `bun test` also executes any compiled `dist/`, whose fixture-resolution failures are build artifacts, not a test population — measured 2026-10-01: 9 → 52 fails with zero source changes), parses the failing population keyed `file > describe > test` (two files hosting the same describe path are two entries — a name-only key collapses them and hides a new red behind a same-named baseline entry), synthesizes a named entry per module-load death (`# Unhandled error` block → `file: load error #N`; bun 1.3.13 **and** 1.3.14 double-count one such death into BOTH its `fail` and `error` summary counters, so accounting is `entries === max(fail, error)`), and **refuses a verdict** (exit 3) whenever the parsed entries cannot account for bun's own counters or the `Ran N tests across M files` line is absent (truncated output) — a parser blind to a failure shape is how a file dying at import turns into a false green. Comparison against the baseline is by **reproduction, never by count**: fresh entries trigger exactly one confirmation re-run, and only names present in BOTH runs are regressions (exit 1) — a deterministic new red cannot hide behind flaky slots, and a fail that does not reproduce is noise whatever its count. Baseline fails that vanish are reported as improvement; ENV-GATE manifests are consolidated into one end-of-run block. First use on a machine: `bun run test:strict -- --learn`, then re-run to compare. **A learned baseline is a snapshot, not an instrument — re-learn it after any land that removes a cause of load-time death.** ⚠ **The repo pins no bun and CI installs `bun-version: latest`: a seat on an older bun is not commensurable with CI** — a bun-only defect is green in CI and red locally (measurements: #391). Classes 2/2b (stale contract, win32 defect — TEST-15) stay red and stay in the baseline by design; a static pin in `env-gate.test.ts` refuses ever gating them.

**PowerShell operations scripts have their own suite**: `bun run test:scripts` (pwsh 7) and `bun run test:scripts:win51` (Windows PowerShell 5.1 — **the interpreter the scheduled tasks actually use**; run both, they do not agree, and the one that ships is 5.1). Pure logic lives in `scripts/lib/claudish-engine.psm1` so it can be exercised without touching Docker, WSL, the task scheduler or the network; the watchdog's glue is tested by dot-sourcing it with an injected `-ClaudishHome` and injected probes. ⚠ **Dot-sourcing `claudish-drain.ps1` runs its `param()` defaults in the caller's scope and clobbers `$ClaudishHome`** — the watchdog saves and restores it around the dot-source, because without that a "sandboxed" run wrote its state to the sandbox and its log to the *production* log (measured 2026-09-20: 2 stray prod lines). Any test claiming a sandbox must assert on the log path too, or it is lying about its blast radius.
