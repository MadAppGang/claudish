## Model Routing (v4.0+)

Syntax `provider@model[:concurrency]` — `google@gemini-2.0-flash`, `or@deepseek/deepseek-r1`, `ollama@llama3.2:3`. Bare names auto-detect (`gpt-4o` → OpenAI, `gemini-*` → Google). Shortcuts (`g@ oai@ or@ openrouter@ mm@ mmax@ mmc@ kimi@ moon@ glm@ zhipu@ gc@ llama@ ll@ litellm@ ollama@ lmstudio@` + aliases) plus any custom-endpoint name: full table in `docs/settings-reference.md` §5.2 — except **`cx@` / `codex@` → OpenAI Codex (Responses API), which that table does not list**; this file is its only record.

Gotchas:

- **A role's `modelMap` entry picks the LANE; since #218 it also pins the VERSION, but only on the native lane and only for `claude-*` targets.** `NativeHandler.handle` forwards `payload.model` verbatim, so before the pin the resolved target never reached the wire and `modelMap.opus` was a no-op on the version axis — measured on the hub 2026-09-22, the map read `claude-opus-4-8` for weeks while **6 487 consecutive native responses over 48 h** were served as `claude-opus-5`, the id the clients named; editing it to `claude-opus-5-5` and reloading still gave 34/34 `claude-opus-5`. `resolveNativeModelPin()` now rewrites the body inside `handleWithCascade`'s loop — there, not at the route, because the cascade re-resolves the handler each attempt and only the attempt landing on `NativeHandler` may carry a bare Anthropic id (the original is restored on a failed attempt, so the mutation never outlives it; `count_tokens` takes the same pin or the client's context accounting drifts). ⚠ **The guard is `startsWith("claude-")`, NOT "is bare" — the two are different predicates and conflating them misfires on this hub**: `sonnet: "glm-5.3"` is bare too, and is kept off the native lane only by resolving to a remote handler; drop it from the routing table and `isNative` (`!includes("/") && !includes("@")`) accepts it, at which point a bare-only guard would put `glm-5.3` on the Anthropic wire — strictly worse than the passthrough it replaced, which at least sent a real Claude id. Kill switch `CLAUDISH_NATIVE_MODEL_PIN=0`, read per request (same container rule as every "read per request" knob: a new value enters a container only at its next recreate — compose carries it, #310); only an explicit `"0"` disarms. There is no Anthropic-side floating `-latest` to point at (dateless ids are pinned snapshots), and the hub holds **no Anthropic credential** (0 non-empty in env and in `config.json`), so it cannot query `/v1/models` to auto-resolve one — #219 tracks doing it from the OpenRouter catalog, where the id spelling differs by **dots vs dashes** (`claude-opus-5.5` vs `claude-opus-5-5`).
- **The native lane refuses to forward a credential that is not Anthropic's (#296), on both `/v1/messages` and `count_tokens`.** Post-swap credential state is checked before the fetch: no credential at all (shape A — the proxy-key swap removed the client's token and no `apiKey` was substituted) or a foreign, non-`sk-ant-` credential (shape B — a Bearer belonging to another party, the WAN-seat shape measured 30/09–01/10 as 40 × upstream `Invalid Bearer <redacted>`) answers locally with a labeled `403 permission_error` and marker `[Native] refused — no Anthropic credential to send (shape=A|B, model=…)`, zero upstream fetch. The `sk-ant-*` OAuth passthrough (ai-01) and the swap-with-`apiKey` path are untouched; kill switch `CLAUDISH_NATIVE_FOREIGN_TOKEN_GUARD=0` (read per request). ⚠ The refusal wording is load-bearing: `isQuotaExhaustion` arms on 403 bodies naming a quota wall, so the message may never contain "usage limit"/"quota exceeded" class words — pinned by test against the real predicate. Since #305, a **mixed** pair (one `sk-ant-` credential + one foreign sibling) is **stripped, not refused** — the `sk-ant-` credential still authenticates (the authorized lane survives whatever the client's header habits), the foreign token never leaves (same pattern as the relay's stale-`x-api-key` drop); same kill switch, and `CLAUDISH_NATIVE_HEADER_NAMES_LOG=1` is the AC-1 instrument (header NAMES only) logging which auth headers reach the native lane. ⚠ **On the hub it sees post-relay headers, not the client's**: a relay deletes `x-api-key` on every forward (`relay.ts`, the stale-proxy-key guard) and a NOMINAL relay never enters `NativeHandler`, so for a relayed client (ai-01's Opus, via its sidecar) the hub can only ever report `authorization` or `(none)`. Only directly-attached clients are measured there. The strip makes that measurement non-decisive: it is safe whatever the client sends.
- **`defaultProvider` is a last-resort fallback, not a front-of-line override.** It is appended to the *end* of each bare-name chain (deduped — `or` ≡ `openrouter`) and only catches models whose chain has zero credentialed providers. Explicit `provider@model` is never affected. Precedence: `--default-provider` > `CLAUDISH_DEFAULT_PROVIDER` > config `defaultProvider` > `OPENROUTER_API_KEY` present > hardcoded `openrouter`.
- **LiteLLM auto-promotion was removed** (commit 5 of the model-catalog/routing redesign; see `default-provider.ts`). `LITELLM_BASE_URL` + `LITELLM_API_KEY` no longer makes LiteLLM the default — set `defaultProvider: "litellm"` explicitly. ⚠ `docs/settings-reference.md` §6.1/§6.3 still documents the legacy promotion; that text is **stale — trust the code**.
- **Vendor prefix resolution is exact-match only** — find the right prefix, never guess the model. Dynamic provider catalogs are PRIMARY; a cold cache falls back to the disk cache (`~/.claudish/all-models.json`, persisted by the last successful refresh), then to **passthrough unchanged** — the static vendor-map fallback was removed upstream and no longer exists (grep before reintroducing one). Resolution happens in `proxy-server.ts` **before** handler construction, through the sync `resolveModelNameSync()` (in-memory caches + `readFileSync` — do not make it async).
- **The slim catalog is PAGED, and a refresh walks it to the server's own end (#635 AC4).** `refreshCatalog()` follows `data.nextCursor` with `cursor=` on the same URL, merging pages and deduping by `modelId`; the walk ends only when the server offers no cursor (or when `data.total` is reached), and every other exit is recorded as INCOMPLETE: a page failure past the first (keep what page 1 gave — never fail a refresh that already succeeded in memory, the #270 doctrine), a replayed cursor, the 10-page cap (`CATALOG_MAX_PAGES`), the deadline. **One deadline covers the whole walk** — the caller's `timeoutMs` is a budget for the refresh, and a per-page timeout would multiply it by the page count. Measured live 2026-10-24: `data.total = 1002` for `limit = 1000`, with `kimi-k3.1-pro` at **index 652** of page 1 — so single-page truncation was NOT why the hub's disk cache lacked it (that was staleness: cache written `15:42:33Z`, catalog generation `16:17:12Z`, and a refresh through the resolver brought it in). What pagination actually fixes is the two models past `limit`, and, above all, the silence: `coverage {pages, fetched, serverTotal, complete}` is persisted on `DiskCacheV2` and returned on `RefreshOutcome.refreshed`, with `[Catalog] partial fetch:` on stderr when incomplete. Coverage describes the `entries` it was measured on, so a writer that REPLACES `entries` drops it instead of inheriting a completeness claim about data it never saw. Pins: `openrouter.test.ts` §"page walk (#635 AC4)" (walk, merge/dedup, page-2 HTTP/network failure, replayed cursor, page cap, page-1 failure, single-deadline bound), `all-models-cache.test.ts` §coverage.
- **Custom endpoints**: `apiKey` expands `${VAR_NAME}` from the environment (never hardcode secrets); entries failing Zod validation **emit a stderr warning and are skipped — they must never crash the proxy**. Endpoints inject themselves through `registerRuntimeProvider()` / `registerRuntimeProfile()` (`providers/custom-endpoints-loader.ts`); the full `customEndpoints` schema (`modelPrefix`, `CLAUDISH_CONFIG_DIR`, per-endpoint key vars) is in `docs/settings-reference.md` §7.
- **`omitReasoningContent`** (custom endpoints, default `false`) drops `reasoning_content` from outbound assistant messages, for backends that validate their body strictly. It is needed because the OpenAI converter emits that field whenever history holds a thinking block — **independent of any opt-in**, since the consumers disagree: DeepSeek *requires* it echoed back, Kimi K2.5 needs it from turn 2, GLM ignores it. Mistral answers `HTTP 422 extra_forbidden` and fails **every** turn of a thinking-mode session. ComposedHandler's thinking-block strip cannot reach it: on the OpenAI wire that strip is a **structural no-op** (it runs after `convertMessages`, by which point content is flattened and reasoning hoisted to a sibling scalar) — hence a separate `stripReasoningContent()` in `openai-messages.ts`. Incident of 2026-08-20 and the measurement that Mistral's `zai-glm-5-2` emits no traces at all: `docs/reference/proxy-pipeline-notes.md`.
- **The MiniMax `forced` thinking chain has TWO filters, and #295 + #324 B1 lift one each (#324).** Outgoing: `MiniMaxModelDialect.shouldFilterThinking()` returns false under `forced`, so the response's thinking block (and its signature) reaches the client. Incoming: ComposedHandler's history strip (the `preserveThinkingInHistory()` gate) used to remove the echoed block before it reached M3 — the chain repaired on one wire and broken on the other (measured by a coordinator probe: forwarded assistant turn carried only `[tool_use]`, M3 fell back to the mute T4a shape). The fix is a per-block hook `preserveThinkingBlock(block)` consulted ONLY inside the strip loop (default false = strip-everything, byte-identical for every other provider); MiniMax overrides it: under `forced`, a block whose signature is unsigned or a **64-lowercase-hex digest** is MiniMax's own and survives intact, anything else is stripped. The discriminant is measured, not supposed: M3's implicit signature is the SHA-256 of the empty string (`e3b0c442…`, fixtures `minimax-m3-anthropic-implicit-signature-r10324/r10416`), M2.5's digests vary but stay 64-hex (`m25-turn1`), `m25-turn2/3` are unsigned — an Anthropic signature is a long opaque base64 blob (the cascade-switch shape: an Opus session that fell to a MiniMax step) and never matches. Deliberately NOT the boolean `preserveThinkingInHistory()`: it also feeds `reasoningRoundtrip` in `convertMessages` (OpenAI wire, `reasoning_content` echo-back); MiniMax lanes run anthropic-sse, where the per-block hook is the only consulted seam, and flipping the boolean would emit `reasoning_content` on OpenAI-shaped routings the policy was never measured on (pinned by unit test). Suites: `composed-handler-minimax-thinking.test.ts` (route, 2-turn, upstream body inspected) + `minimax-model-dialect.test.ts` (discriminant matrix).
- **M3.1-Flash rejects `thinking.type:"disabled"` with 400/2013 — the dialect rewrites it to `adaptive` under every policy (fix 2026-10-21).** Flash cannot think less than adaptive (`"requires adaptive thinking; thinking.type='disabled' … is not allowed"`, error 2013), and the `effort:` policy deliberately never touches `thinking` — so a client-disabled request reached the wire verbatim and took the 400 straight back to the client. Measured live: WebFetch one-shots (`msgs=1`, haiku role, `{"type":"disabled"}` — the CC summarization path's saving switch), 9 requests 2026-10-21 16:21Z→21:00Z across po-2025/ai-01/po-2023, each a 400 with the client falling back to its secondary fetch path. The guard is a **MODEL constraint, not an operator preference**: it runs after the policy block (an operator `disabled` armed on Flash is caught too), on the anthropic wire only, and picks `adaptive` — the minimum Flash accepts — rather than dropping the field, which would reset Flash to its **MAX-when-omitted** default. M3 keeps `disabled` (it accepts the off switch). Pin: `minimax-model-dialect.test.ts` describe "M3.1-Flash disabled guard (400/2013)".
- **Local model APIs report `prompt_tokens` as the FULL conversation context each request**, not a delta. `writeTokenFile` therefore assigns (`=`) input tokens rather than accumulating (`+=`).
- **The three input counters ship TOGETHER on every terminal `message_delta`, and a zero `input_tokens` is a trap (#179).** `splitPromptTokens()` (`stream-parsers/usage-cache-split.ts`) derives `input_tokens` / `cache_read_input_tokens` / `cache_creation_input_tokens` from `prompt_tokens` in ONE place, clamped so the three always sum back to it — because **Claude Code reconstructs the conversation size by summing them raw**, with no coalescing (verified in the shipped bundle, identical in 2.1.17 and 2.1.273: `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`, feeding the occupancy percentage). Two consequences that look like style and are not: (a) emitting a reduced `input_tokens` **without both siblings** understates the context by exactly the cached share — the shape #99 was opened for, which silently disarms auto-compaction; (b) `message_start` must seed both cache counters at an explicit **0**, because the client's per-key merge takes a delta only when it is `> 0` (`K.x !== null && K.x > 0 ? K.x : A.x`) and an absent seed key therefore returns `undefined`, turning that raw sum into `NaN` — `output_tokens` uses `??` and coalesces, the three input counters do not. Hence the **`fullyCached` unsplit rule**: on a turn whose input is entirely cache, `input_tokens: 0` would be *discarded* and the previous turn's seed kept beside a full-size `cache_read`, roughly doubling the reported context — so that turn ships as ordinary input instead. Our `toAnthropicUsage` has **5 call sites** (all `message_delta` → `message_stop`, incl. the #65 policy-refusal path), which is wider and more consistent than upstream's single inlined site. ⚠ Read counters by **observed** spelling, never invented: `prompt_tokens_details.cached_tokens` *and* DeepSeek's top-level `prompt_cache_hit_tokens` (`??`, not `||` — a reported 0 has spoken), plus `cache_write_tokens` for creation (no producer on our lanes: 0 occurrences measured). Cost rides in a separate `detail` argument and is **inert today** — `cacheReadCostPer1M` has zero producers, so every discount computes to exactly 0. The OpenAI-shaped parsers both ship it — `openai-sse` (4 sites) and, since #195 (#186, closed 2026-09-21), the Codex lane `openai-responses-sse` (its six `finalUsage()` emissions share one `toAnthropicUsage` site). Since #444 **all five stream parsers** — including `gemini-sse` and `ollama-jsonl`, which previously seeded `{input_tokens: 0, output_tokens: 0}` with no cache counters — seed via `messageStartUsage(priorInputTokens)` and shape their terminal deltas through `toAnthropicUsage`; the Gemini-camelCase `usageMetadata` is mapped to the openai shape **at the parser call site**, never inside the shared shaper (one provider's dialect must not enter a helper every lane reads). Pins: `usage-shape-gemini-ollama.test.ts`.
